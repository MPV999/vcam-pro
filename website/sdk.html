Virtual Camera SDK

The SDK produces frames inside your app. It cannot and does not replace the camera for other applications — Android offers no public API for that. Any app that links the SDK receives real frames from the VCAM pipeline.

Add the dependency

// settings.gradle.kts
include(":virtual-camera-sdk:api")
include(":virtual-camera-sdk:format")
include(":virtual-camera-sdk:frames")
include(":virtual-camera-sdk:playback")
include(":virtual-camera-sdk:source")

// your app module
dependencies {
    implementation(project(":virtual-camera-sdk:source"))
}

Create a session

val session = VirtualCameraSdk.createSession(
    config = VirtualCameraConfig(
        configuration = FrameConfiguration(1280, 720, 30, FrameFormat.RGBA_8888),
        bufferCount = 4,
    ),
    consumer = FrameConsumer { frame ->
        // frame.data is a direct ByteBuffer; copy what you need, then release.
        render(frame)
        frame.release()
    },
)

// video
session.useSource(VirtualCameraSdk.videoSource(context, uri))

// still image, rendered continuously at the configured FPS
session.useSource(VirtualCameraSdk.imageSource(context, uri))

// live camera
session.useSource(
    VirtualCameraSdk.physicalCameraSource(context, lifecycleOwner, CameraSelector.LENS_FACING_BACK)
)

Transport

val playback = session.playback()   // null for live sources
playback?.play()
playback?.pause()
playback?.seekTo(2_000_000L)
playback?.setLooping(true)

Rules the SDK enforces

  • Bounded buffers. A slow consumer causes dropped frames, never unbounded memory.
  • Every frame must be released; the pool is the backpressure mechanism.
  • Source switches are serialised, so rapid switching cannot crash teardown.
  • Typed SourceError failures instead of silent stalls.

Honest limitations

  • Frames are delivered to your process only. Other apps cannot see them.
  • Output is produced by GPU read-back plus an optional CPU YUV conversion; RGBA is the cheapest format.
  • Decoded output uses the codec's buffer size, so a padded stream (e.g. 1920x1088) is reported at that size.
